为什么要有这门课

Hopper 改变的是编程模型，而不只是吞吐数字。

本站关注 Hopper 的真实工作方式：异步执行、描述符驱动的数据搬运、同步语义、张量核心数据流， 以及 H100 规模所要求的分布式系统上下文。

01

异步执行是整个故事的核心。

过去的 CUDA 直觉把发射和完成几乎当成同一个心智单元。Hopper 让重叠（overlap）、等待逻辑 与生产者/消费者协调成为日常内核设计的一部分。

02

数据搬运是一等公民级别的优化面。

当你想让张量核心持续有数据可算时，TMA 描述符、swizzle、布局选择、共享内存暂存 以及与 barrier 关联的传输，和数学运算本身同样重要。

03

规模是架构的一部分，不是可选附录。

NVLink、Stream-K 调度、NCCL 初始化、PMIx 和 Slurm 会出现在课程里，因为真实的训练系统 不会止步于单 GPU，心智模型也不应该。

深度解读

四条经过刻意设计的课程入口。

上面的课程表展示了完整的攀登路线。这一节收得更紧：四个高信息量的入口， 覆盖机器模型、同步、内核设计与分布式编排，同时不把首页变成又一份完整的课程索引。

第 01 课

H100 简介

先把 Hopper 当作一台机器来看：架构、内存层级、SMSP、张量核心、调度器， 以及异步执行为什么改变了后续课程的阅读方式。

  • 建立从 HBM 经 L2、共享内存到寄存器的内存路径心智模型。
  • 先看清 TMA 和 WGMMA 的位置，后面的课程再把它们变成具体的内核机制。
  • 把整门课锚定在利用率、重叠（overlap）与 GPU 真实的执行层级上。
Hopper 内存层级 TMA WGMMA

第 03 课

异步与屏障

从架构进入同步：proxy 分离、RAW 与 WAR 冒险、mbarrier、 集群 barrier、异步组，以及让重叠（overlap）正确而非碰巧正确的规则。

  • 理解 Hopper 为什么需要跨通用 proxy 与异步 proxy 的显式可见性和顺序性。
  • 弄清 mbarrier 追踪什么、phase 如何翻转，以及 acquire 语义为什么重要。
  • 把 TMA、cp.async.bulk、WGMMA 消费与共享内存所有权交接串联起来。

    代码锚点

    课程始终贴近内核源码。

    这些参考文件就在仓库里。课程正是在这里把架构图与调度器逻辑、共享内存布局、 描述符构造和实测内核连接起来。

    sm90_gemm_tma_warpspecialized_pingpong.hpp

    一个 CUTLASS SM90 内核：ping-pong 分阶段暂存、warp 专用化的生产者与计算组、 有序序列屏障，以及与调度器联动的共享存储。

    sm90_tile_scheduler_stream_k.hpp

    持久 Stream-K 分解、工作 tile 记账、规约单元， 以及决定工作如何跨机器流动的调度器规则。

    fast.cu/examples/matmul/matmul_12.cuh

    共享内存矩阵描述符、内联 PTX、显式 warpgroup fence， 以及在 bf16 GEMM 内核中直接使用 wgmma.mma_async。

    fast.cu/README.md

    从零实现的内核与实测 bf16 matmul 结果， 其中包括在部分 H100 矩阵规模上超过 cuBLAS 的运行。
