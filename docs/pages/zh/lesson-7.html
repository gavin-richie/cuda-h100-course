本课的重要性

异步张量核心的发射会变成一条你必须关闭、排空、写回、有时还要压缩的流水线（pipeline）。

Part 1 引入了 warpgroup 发射。Part 2 要解释的，是让这套发射模型得以在真实 kernel 中存活的东西： 组边界、等待深度、寄存器冒险控制、累加器导出、FP8 传输规则，以及稀疏 MMA 的元数据路径。

关键要点

  • wgmma.commit_group 与 wgmma.wait_group<N> 是流水线深度控制，而不是通用屏障（barrier）。
  • wgmma.fence 为 WGMMA 排序寄存器冒险，但共享内存（shared memory）可见性仍然需要正确的、具备 proxy 意识的栅栏（fence）。
  • stmatrix、FP8 打包（packing）与 sparse metadata 正是让异步张量核心结果在完整 kernel 中可用的东西。

为什么生命周期控制很重要

wgmma.mma_async 会立即返回。这正是 Hopper 能够让张量数学与 TMA 加载、指针工作以及为下一个 tile 做 staging 相互重叠的全部原因。但一旦数学运算变成了异步的，程序还需要一种办法来把发射打包成组、 限制在途数量，并知道累加器何时才真正可以安全消费。

按批次跟踪，而不是逐个跟踪 MMA

讲义明确指出，组的存在就是为了让硬件不必对每一条 MMA 独立做 scoreboard 跟踪。一个 tile 的发射量由此成为一个可跟踪单元。

只在下一阶段需要时才排空

你通常不会想在每个发射窗口后面都放一个“等待一切”的屏障。你会让一些组保持在途、为下一批工作做 staging，只有在消费寄存器或执行 store 之前才完全排空。

值得记住的模式：发射一个批次，提交它，开始准备下一个批次，只等到在途深度回落到期望的窗口为止；而当你真正需要完全物化的结果时，使用 wait_group 0。

提交、等待与栅栏定义了 WGMMA 生命周期

分组给了 WGMMA 流水线友好的粒度。当前这批异步 MMA 会一直保持“打开”状态，直到你用 wgmma.commit_group.sync.aligned 把它关闭。之后，wgmma.wait_group 让 warpgroup 只在已提交的批次中仍有太多在途时才停顿（stall）。 

// One output-tile worth of async math
wgmma.mma_async ...
wgmma.mma_async ...
wgmma.commit_group.sync.aligned;

// Prepare the next tile while some math still runs
// TMA, pointer math, shared-memory staging, etc.
wgmma.wait_group.sync.aligned 1;

// Before reading accumulators or exporting them
wgmma.wait_group.sync.aligned 0;
指令 它做什么 它不做什么
wgmma.commit_group 关闭当前批次，让硬件可以把它当作一个已提交的组来跟踪。 它不会等待完成。
wgmma.wait_group N 停顿，直到只剩 N 个已提交的组仍在途。 它不是那种“永远同步所有张量工作”的一揽子原语，除非 N = 0。
wgmma.fence.sync.aligned 标记 warpgroup 发射边界，并为 WGMMA 排序累加器/寄存器来源操作数的冒险。 它不是面向 TMA 或共享内存可见性的异步 proxy 栅栏。

本课对最后这个区别非常谨慎。wgmma.fence 关心的是 WGMMA 流水线本身，尤其是累加器和驻留在寄存器中的 A 碎片。如果共享内存的内容是经由异步 proxy 路径产生的，那么在消费它之前，你仍然需要正确的跨 proxy 发布规则。

stmatrix 是不透明累加器碎片变成可用 tile 的途径

当 WGMMA 结束时，结果并不是以干净的行主序（row-major）矩阵形式躺在寄存器里。它按照张量核心内部使用的精确布局（layout），碎片化地分布在 128 个线程之中。stmatrix 就是那条协作式（cooperative）store 指令，把这些碎片以正常的矩阵布局写回共享内存。

类似 ldmatrix，但方向相反

数据所有权与地址所有权是解耦的。线程提供它们所持有的寄存器，以及把这些碎片落进正确的行主序目的地所需的地址。

仍然是 tile 结构化的

基本原子（atom）是 m8n8 矩阵 tile。像 .x4 这样的变体让每个线程贡献四个已打包的寄存器，从而可以一次一片（slice）地序列化出更大的逻辑 tile。 

// From the repo's matmul_12.cuh epilogue flow
// convert/pack fragments
// stmatrix.sync.aligned.m8n8.x4.trans.shared::cta.b16 [...]
// bar.sync across the warpgroup
// issue TMA store for the completed tile

FP32 累加器是重要的注意事项

stmatrix 不支持 .f32 数据。它支持打包的 .b16 和 .b8 形式。所以如果 WGMMA 累加到了 FP32 寄存器里，你不能把这些寄存器直接喂给 stmatrix。你必须先向下转换（downcast）并打包这些值，这正是 FP32 输出路径通常在共享内存 store 之前包含一个显式转换循环的原因。

为什么存在这个循环：一个逻辑输出 tile 通常大于单次 stmatrix.x4 调用所能覆盖的范围，所以 epilogue 会把累加器切片逐个序列化、写进共享内存，然后把 tile 交给稍后的 TMA store 路径。

FP8 既是一个传输与布局问题，也同样是一个精度选择

Hopper 的 FP8 路径很重要，因为它同时改变了数学吞吐量与操作数契约。本课把 FP8 定位为一种压缩训练格式：它仍然以 FP32 累加，但它的范围、缩放（scaling）、打包与布局决策可以决定正确性与性能的成败。

格式 它偏向什么 它为什么会出现
e4m3 更多的尾数精度，更小的动态范围。 在范围可控时，常用于激活值和权重。
e5m2 更大的动态范围，更少的尾数精度。 对梯度和幅度波动更大的路径很有用。

缩放是让 8 位浮点保持有用的逃生通道。张量级（tensor-wise）、向量级（vector-wise）与块级（block-wise）方案之所以都存在，是因为原始 FP8 的范围太过局促，没有量化策略就无法信任。讲义还点名了 .satfinite 转换形式，让超出范围的值被钳制（clamp）住，而不是爆炸成不可用的结果。 

// Representative PTX conversion style
cvt.rn.satfinite.e4m3x2.f16x2 ...
cvt.rn.satfinite.e5m2x2.f32 ...

x4 打包填满寄存器

e4m3x4 和 e5m2x4 把四个 FP8 值放进一个 32 位寄存器。这就是自然的存储与传输形式。

x2 打包匹配数学路径

e4m3x2 和 e5m2x2 是 16 位打包形式，与 Hopper 摄取低精度数学碎片的方式正好对齐。

Hopper FP8 WGMMA 有更严格的操作数规则

课程讲义点名了固定的 m64nNk32 FP8 形状，以及一个关键的 Hopper 限制：那条显而易见的 ldmatrix ... .b8 路径并不是 SM90a 在这里暴露的东西。这就是为什么实用的 Hopper FP8 kernel 往往要么对两个操作数都使用共享内存描述符（descriptor），要么走 RS 路径——用普通的共享内存加载把 A 装进寄存器，并已按 WGMMA 期望的布局打包好。

同一份讲义还强调了严格的 K-major 规则。与 FP16/BF16 形式不同，FP8 WGMMA 不会给你同样的转置逃生通道。如果暂存的操作数 tile 还不是 K-major 的，你就得为额外的重打包和同步付出代价，之后张量核心才能消费它们。

数值上的提醒：即使文档写明的累加器类型是 FP32，本课也援引了实证报告：FP8 累加的行为可能像一种降低精度的 FP32 变体。大 K 的归约（reduction）可能需要 K 切分（K-slicing）或分阶段累加，才能把误差增长控制住。

稀疏 WGMMA 增加了第二份契约：元数据正确性

稀疏 WGMMA 仍然是矩阵乘累加（matrix multiply-accumulate），但硬件假设了一种非常特定的结构化稀疏模式。支持的模型是稀疏 A 乘稠密 B。A 携带压缩后的数据，外加告诉张量核心幸存值属于哪里的元数据。

sp_meta

一个打包寄存器，包含幸存元素的位置元数据。对于 2:4 稀疏度，它记录每个四元组（quartet）中有哪两个索引留存下来。

sp_sel

一个选择器（selector），告诉硬件哪些线程负责为当前指令形状呈现元数据。如果该选择器与实际的加载策略不匹配，张量核心就会读到错误的元数据。

情形 讲义中的选择器规则 为什么重要
FP16 / BF16 稀疏 sp_sel 可以任选一对贡献线程。 让你可以把选择器匹配到元数据实际被加载的位置。
FP8 / INT8 稀疏 sp_sel 必须为 0。 对这些形状，讲义把任何其他值都视为未定义。
复制式元数据加载器 使用简单的选择器，并把相同的元数据广播给相关线程。 降低元数据所有权错位的机会。

物理稀疏规则是 2:4。你不能只是扔掉两个值然后听天由命。你必须存储幸存者，外加足够的元数据，让硬件能在每个四元组内重构它们的原始位置。错误的元数据不会优雅降级。它只会让张量核心读到错误的稀疏模式。

实践指导

  1. 用发射窗口来思考。把异步 MMA 分批组织进逻辑组，然后选择一个能保持重叠的等待深度，而不是塌缩回完全串行化。
  2. 只在消费时排空。在读取累加器、用 stmatrix 导出它们，或者以其他方式把结果当作完成之前，使用 wait_group 0。
  3. 把寄存器排序与内存可见性分开。wgmma.fence 不能替代 TMA 支撑的流水线所使用的异步 proxy 发布规则。
  4. 把 FP8 当作一份布局契约。缩放、打包、K-major staging 与转换策略，和名义数据类型同等重要。
  5. 绝不要对 sparse metadata 含糊其辞。只有当载荷与选择器逻辑精确匹配时，稀疏张量核心才能工作。

术语表

wgmma.commit_group 关闭当前这批异步 MMA，让硬件可以把它当作一个已提交的组来跟踪。
wgmma.wait_group 限制还有多少个已提交 WGMMA 组保持在途的等待原语。
stmatrix 协作式矩阵 store 指令，把张量核心碎片从寄存器写回共享内存。
e4m3 / e5m2 Hopper 的两种 FP8 浮点格式，在尾数精度与动态范围之间做取舍。
sp_meta 打包的元数据，告诉稀疏张量核心来自稀疏 A 的幸存非零值应当属于哪里。
